Mofu docs

Everything you need to use Mofu in your browser and in your terminal.

Getting started

In your browser

  1. Open the app. There's no account.
  2. Pick a mode at the top: General, Data Analyst, Study Buddy or Dev Tools.
  3. Ask a question or load a file. Before your first message there's a quick bot check (Cloudflare Turnstile).

You get 10 free messages a day. Holding 1,000,000 or more $MOFU raises that to 30: open Settings, choose Connect wallet and sign the message (no transaction, no gas). Or add your own OpenRouter key in Settings for no limit.

In your terminal

You need Node.js 22 or newer and an OpenRouter key from openrouter.ai/keys. 

npx mofu-cli auth     # save your key once (~/.mofu/config.json)
npx mofu-cli          # chat in the current folder

Or set OPENROUTER_API_KEY for the current shell; it takes priority over the saved key.

The web app

Each mode gives Mofu different tools. Switching modes keeps your memory and settings.

General
Questions and explanations. Mofu can look things up on Wikipedia, define words and remember facts you ask it to (stored in your browser; see Memory at the top).
Data Analyst
Analyze a spreadsheet with real calculations. More below.
Study Buddy
Summaries, flashcards and quizzes from a PDF, notes or an article. More below.
Dev Tools
Explain a GitHub repository, scan dependencies, work with an API spec, scan a token on Robinhood Chain. More below.

The LED badge next to the logo shows what Mofu is doing: READY, THINKING, ANALYZING, STUDYING, SCANNING, DONE or ERROR.

Data Analyst

Drop a CSV, TSV, Excel (.xlsx) or JSON file, up to 20 MB. Your file is opened in your browser and never uploaded. Mofu profiles it first: columns and types, missing values, duplicates, mixed formats and outliers.

Then ask in plain English. Mofu answers by running Python (pandas, matplotlib) in a sandbox in your browser, so every number comes from real code. Charts appear in the chat with a download link.

It can join your data with public sources:

  • daily exchange rates (Frankfurter, from the European Central Bank)
  • public holidays (Nager.Date)
  • historical weather (Open-Meteo, non-commercial use)
  • country facts and indicators like GDP or inflation (World Bank)

Generate report writes up the analysis, and Download report saves it as Markdown with the charts. The first time you use this mode, the browser downloads the Python runtime (Pyodide), which takes a moment.

Study Buddy

Upload a PDF, .txt or .md file, or paste a link to an article. Use the page range for long PDFs: 30 pages at a time on the free tier, 300 with your own key. Scanned PDFs (images of pages) have no text to read and aren't supported yet.

  • Summary, Detailed summary, Explain like I'm 12: three levels, with page citations.
  • Flashcards: flip a card, mark whether you knew it, and it comes back on a schedule (1, 3, 7, 14 days). Export for Anki downloads a file Anki imports.
  • Quiz me: multiple choice is graded instantly; short answers are checked by Mofu against the document. Ask for Harder or Easier.

Mofu reads only the pages it needs and cites them, like "(page 4)". It can also look things up on Wikipedia, find papers on arXiv and books on Open Library, and format citations from a DOI.

Dev Tools

Explain a repo

Paste a public GitHub URL. Your browser reads the file tree, manifests, README and a few entry points, and Mofu explains how the project works. It's read-only; to change code, use the CLI.

Scan dependencies

Upload package.json with package-lock.json, requirements.txt or pyproject.toml, or paste a GitHub URL. Every package is checked against OSV for known vulnerabilities and against deps.dev for deprecated or unmaintained releases, right in your browser. Then ask for an upgrade plan. Any vulnerability ID or version Mofu mentions that isn't in the scan is flagged.

API spec

Load an OpenAPI 3 or Swagger 2 spec (JSON or YAML) by upload, paste or link. It's validated in your browser, with the exact path of any error. Then:

  • Generate tests: test cases checked against the spec, downloadable as JSON, a Vitest file or an .http file.
  • Generate docs: Markdown docs with parameter and response tables and examples.
  • Compare with another version: breaking and non-breaking changes, decided by Mofu's rules, not by AI.

The web app never sends requests to your API. To run the tests, use npx mofu-cli api test.

Scan a token

Paste a token contract address on Robinhood Chain. Mofu reads the contract straight from the chain and answers, in plain English: can new tokens be minted, can transfers be paused, can wallets be blocked, can fees or trading limits be changed, can the code be swapped (upgradeable proxies), and who controls it. Supply, owner and burned share are shown too.

The scan is Mofu's own code reading bytecode and storage, not AI. Choose Explain this to have Mofu talk you through it (that uses a message). Every scan also has a public page with a share card: mofu.works/token/0x….

Can you sell it? Mofu simulates a small buy and an immediate sell where the token trades (on a Pons launch curve: a real buy for 0.001 ETH and a sell, on a pool: tokens moving in and out the way a swap does). Nothing is sent. You see whether the sell went through, the buy and sell tax, and on a curve how much ETH came back.

How deep can you sell? When the sell works, Mofu also measures how big one sale can be before the price drops 10%. On a launch curve it simulates sells of growing size (from a sliver of the supply up to a fifth of it); on a pool paired with WETH it works it out from the pool's reserves.

Seen this code before? Scammers redeploy the same honeypot contract under new names. Mofu fingerprints each contract's code (leaving out the compiler's metadata and addresses baked in at deploy time) and remembers which fingerprints belonged to tokens whose simulated sell failed. A new token built from that code is flagged, under any name. A widely used template isn't flagged just because one copy misbehaved: honeypots have to outnumber the copies that sold fine.

Is it the real one? If other tokens Mofu has seen use the same name or ticker, the scan lists them and says which came first. Anything that calls itself MOFU but isn't the official contract is called out.

With the full report (for $MOFU holders) you also see the top 10 holders, with pools and burned tokens labeled, and who created the token: the creator wallet, how old it is, how much it still holds and whether it launched other tokens through the same launcher, with each of those launches marked active or quiet. Everyone sees the top 10 share and a flag when one wallet holds more than 10% or 20%.

Check a wallet and revoke approvals

Paste a wallet address in the same box, or choose check my wallet's approvals. Mofu lists every token approval the wallet has given that is still active (re-checked on the chain), says who the spender is (a known contract, a launch curve, a pool, or a plain wallet, with its age and how busy it is) and flags the risky ones: spenders that are plain wallets, brand-new little-used contracts, and unlimited approvals. It also lists the tokens the wallet holds, each with a quick scan.

Lookalike addresses. Wallet Health also reads the wallet's last 100 transactions for address poisoning: transfers someone else made from or to an address that starts and ends like one you send to (or like your own), and 0-token transfers "from" you that you never made. Never copy an address from your history; Mofu Guard stops a send to a lookalike before your wallet sees it.

Revoke sends one transaction from your wallet, approve(spender, 0), which removes the permission and can't move your tokens. It's the only transaction Mofu ever offers. Approvals for whole NFT collections aren't checked yet.

Explain a transaction

Paste a transaction hash in the same box (0x plus 64 characters). Mofu decodes it: who sent what to whom, mints and burns, and approvals. Unlimited approvals and approvals to plain wallets are flagged, since that's how most wallet drains start. Share it with mofu.works/app/?tx=0x….

It looks for common function names, so a contract that hides or renames them can't be fully judged, and it doesn't cover liquidity depth or price. It's a technical check, not financial advice.

Use Mofu in your AI app (MCP)

Mofu runs an MCP server, so AI apps that support the Model Context Protocol can use its tools directly. Nothing to install: add this URL. 

https://mofu.works/mcp

Tools

  • scan_token: the Token Scanner. Give it a contract address on Robinhood Chain and it reports what the code allows (mint, pause, blacklist, fees, limits, upgrades, owner, burned share) and how concentrated the holders are.
  • explain_transaction: give it a Robinhood Chain transaction hash and it decodes the transfers, mints, burns and approvals, flagging risky approvals.
  • check_wallet: give it a wallet address on Robinhood Chain and it lists the active token approvals, who each spender is and which are risky, plus the tokens the wallet holds. Handy for agents: check before you trade, and know what to revoke.
  • check_dependencies: give it package.json, package-lock.json, requirements.txt or pyproject.toml and it returns known vulnerabilities, the version that fixes them and how far behind each package is.
  • scan_secrets: give it files and it finds wallet private keys, seed phrases, PEM keys and API tokens, values redacted. It sees only the text you pass, not git history.
  • audit_solidity: give it Solidity files and it says what Mofu's Token Scanner will likely flag once deployed, plus common bugs, with line numbers.

All of them are Mofu's own code reading real data, not a model. Your AI app explains the results. Up to 50 tool calls a day per IP address (shared with the API), no account needed.

Claude Code

claude mcp add --transport http mofu https://mofu.works/mcp

Claude Desktop and claude.ai

Settings → Connectors → Add custom connector, then paste the URL.

Cursor

Add to ~/.cursor/mcp.json (or .cursor/mcp.json in a project): 

{ "mcpServers": { "mofu": { "url": "https://mofu.works/mcp" } } }

VS Code

Add to .vscode/mcp.json:

{ "servers": { "mofu": { "type": "http", "url": "https://mofu.works/mcp" } } }

Then ask, for example: "Scan the token 0x… on Robinhood Chain" or "Check this package.json for vulnerabilities".

For agents and bots: API, CLI checks and webhooks

The Token Scanner and Wallet Health are also a plain JSON API, so scripts, bots and trading agents can check a token or a wallet before they act. No account and no key. Calls share one allowance with the MCP server: 50 a day per IP address.

Endpoint What you get
GET /api/v1/token/{address} The Token Scanner report: verdict (clean, caution or risky), every check, the sell test, lookalikes
GET /api/v1/wallet/{address} Wallet Health: approvals with risk and reasons, holdings
POST /api/v1/webhooks Watch tokens and get a signed POST when one changes (below) 
curl https://mofu.works/api/v1/token/0xf76593c1c321c2a2f77775025e9677999ce7ea8c

Responses carry X-RateLimit-Remaining and X-RateLimit-Reset. Errors are { "error": { "code", "message" } } with a matching HTTP status (429 when the day's allowance is used up).

In your terminal

The CLI has the same checks. They don't need an OpenRouter key.

npx mofu-cli scan 0xTOKEN       # what the contract allows, sell test, copycats
npx mofu-cli wallet 0xWALLET    # every approval, risky ones flagged, holdings
npx mofu-cli scan 0xTOKEN --json                 # the raw report, for scripts
npx mofu-cli scan 0xTOKEN --fail-on risky        # exit code 2 if the verdict is risky

--fail-on caution fails on anything that isn't clean. For a wallet, --fail-on risky fails when any approval is risky and caution also when one is unlimited. Exit code 1 means the check couldn't run.

Webhooks

Mofu watches up to 10 tokens per webhook and POSTs JSON to your https URL when one of these happens:

Event When
owner_changed The owner address changed, including a renounce
supply_changed Total supply went up (minted) or down (burned)
upgraded A proxy's implementation (the code that runs) was swapped
pause_changed Transfers were paused or unpaused
liquidity_dropped ETH on the launch curve, or WETH in the pool, fell 30% or more between two checks (on a curve this also happens when the token graduates)
verdict_changed Mofu's verdict changed, seen on two scans in a row

Create one with the CLI or the API. Leave out events to get all six.

npx mofu-cli webhook add https://your.domain/mofu 0xTOKEN --events owner_changed,liquidity_dropped

curl -X POST https://mofu.works/api/v1/webhooks \
  -H "Content-Type: application/json" \
  -d '{"url":"https://your.domain/mofu","tokens":["0xTOKEN"]}'

Mofu first sends a ping event and saves the webhook only if your URL answers with a 2xx status. The answer includes the webhook's id and a secret that's shown once. Keep it: it signs every event and it's the only way to manage the webhook (Authorization: Bearer <secret> on GET, DELETE and POST …/test, or mofu webhook status|test|remove).

An event looks like this:

{
  "id": "evt_…",
  "type": "owner_changed",
  "createdAt": "…",
  "token": { "address": "0x…", "name": "…", "symbol": "…" },
  "summary": "$TKN: the owner changed from 0xaaaa…aaaa to 0xbbbb…bbbb.",
  "before": "0xaaaa…",
  "after": "0xbbbb…",
  "report": "https://mofu.works/token/0x…",
  "webhook": "wh_…"
}

Each request has Mofu-Event, Mofu-Delivery and Mofu-Signature: t=<unix seconds>,v1=<hex>, where v1 is HMAC-SHA256 of t + "." + body with your secret. Check it, and reject events whose t is more than a few minutes old: 

import { createHmac, timingSafeEqual } from "node:crypto";

function fromMofu(header, rawBody, secret) {
  const { t, v1 } = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;
  const expected = createHmac("sha256", secret).update(`${t}.${rawBody}`).digest();
  const given = Buffer.from(v1 ?? "", "hex");
  return given.length === expected.length && timingSafeEqual(given, expected);
}

How often: owner, supply, code, pause and liquidity are read every few minutes. The full scan behind the verdict reruns every few hours per token. Deliveries time out after 5 seconds and aren't retried. After 20 failed deliveries in a row a webhook is switched off (a successful test switches it back on), and it's deleted a week later. Limits: 5 new webhooks a day per IP, 3 per URL.

SDK

mofu-sdk wraps the API for TypeScript and JavaScript, with no dependencies (Node.js 18+, browsers, Workers, Deno, Bun): 

npm install mofu-sdk

import { Mofu, parseWebhook } from "mofu-sdk";

const mofu = new Mofu();
const { report } = await mofu.scanToken("0x…");
const d = await mofu.checkBeforeBuy("0x…", { minSellDepthEth: 0.5 });
if (!d.allowed) console.log(d.reasons);

// in your webhook handler
const event = await parseWebhook(signatureHeader, rawBody, secret);

checkBeforeBuy applies a buy rule you can tune (verdicts, taxes, a failed or missing sell test, lookalikes, sell depth) and says no when Mofu can't be reached. See the SDK README.

Trading agent template

examples/safe-trading-agent is a starting point for an agent that asks Mofu before every buy. The check sits inside the buy function, so no strategy (and no AI model calling it as a tool) can skip it. If Mofu can't be reached, the answer is no. It includes a webhook receiver that pauses a token when it changes. Bring your own strategy and wallet code; out of the box it's a dry run.

The CLI

Run Mofu inside a project folder. It can only read and change files inside that folder, and it asks before it edits a file (showing you the diff), runs a command or touches git.

Install it once with npm install -g mofu-cli and the command is mofu. Without installing, write npx mofu-cli wherever the table says mofu.

Command What it does
mofu Interactive chat in the current folder
mofu "question" One answer, then exit
mofu task "instruction" A coding task on a branch, with your tests
mofu explain Explain the repository you're in
mofu tests <path> Write and run unit tests for a file or folder
mofu analyze <file> Data Analyst on a CSV, Excel or JSON file
mofu study <file-or-url> Study Buddy; --pages 40-90 for long PDFs
mofu deps Scan dependencies; --json for raw data, --fix to upgrade
mofu api docs|tests|test|diff Docs, test cases, test runs and diffs from an API spec
mofu auth Save your OpenRouter key
-m, --model <id> Use another model for this run

In a chat, type /help for commands:

/model [id] Show or switch the model
/clear Start a fresh conversation
/memory, /forget Show or clear what Mofu remembers (~/.mofu/memory.md)
/exit Quit. Ctrl+C stops a reply that's running.

Coding tasks

mofu task "add a --verbose flag" works like a careful colleague:

  1. Maps the repository and reads only what it needs.
  2. Shows a short plan and waits for you to accept or change it.
  3. Creates a mofu/<task> branch, makes the edits and adds tests.
  4. Runs your tests and fixes failures, at most three times, then explains.
  5. Commits only the files it changed, and opens a pull request only if you say yes (needs the GitHub CLI).

It never commits on your default branch and never force-pushes. Those rules are enforced in code, not just asked of the model.

Study, data, deps and APIs in the terminal

  • mofu study notes.pdf: /summary short|detailed|eli12, /flashcards, /review (practice due cards), /quiz, /export deck.tsv (for Anki).
  • mofu analyze sales.csv: charts are saved to ./mofu-output/. The first run downloads the Python packages (about 30 MB) once.
  • mofu deps --fix: pick upgrades, apply them on a branch with your package manager, run the tests and commit.
  • mofu api test openapi.yaml --base-url http://localhost:3000: shows the host and request count and asks first; warns if the host isn't local. Add --auth-header "Authorization: Bearer …" (never printed) and --yes for CI. Reports go to ./mofu-output/.

For builders: secrets, contract checks, reviews and CI

Three of these are plain code that runs on your machine: no AI, no API key, nothing sent anywhere. mofu review is the one that uses a model (your OpenRouter key).

Find leaked secrets

npx mofu-cli secrets               # files and the whole git history
npx mofu-cli secrets --no-history  # just the files
npx mofu-cli secrets --json

It looks for wallet private keys, seed phrases (12 to 24 recovery words, checked against the BIP39 checksum), PEM private keys and API tokens with a known format (OpenRouter, OpenAI, Anthropic, GitHub, npm, Stripe, AWS, Google, Slack, Telegram, GoldRush), plus committed .env and key files. It reads every commit, so it also finds a key that was deleted later but is still in the history. Values are shown with only their first and last characters. Hardhat's and Anvil's public test keys are listed as such and don't fail the run.

Exit code 2 means something was found. A false alarm? Put mofu-secrets: ignore in a comment on that line. A real leak: revoke the key at the provider, and move funds out of a leaked wallet. Deleting the line doesn't remove it from git history.

Check a contract before you deploy

npx mofu-cli audit contracts/Token.sol
npx mofu-cli audit contracts --fail-on risky

mofu audit reads Solidity source and tells you what Mofu's Token Scanner is likely to say once the token is live: can the owner mint, pause, block wallets, change fees without a cap, set trading limits, upgrade the code, edit balances or treat sells differently. It also flags common bugs: tx.origin checks, unchecked low-level calls, ETH sent before storage is updated (reentrancy), block-based randomness and old compilers. Every finding has a line number.

It's pattern matching on the source, not a compiler and not an audit: it can miss things and flag things that are fine. Contracts that will hold real money deserve a review by people.

AI code review

npx mofu-cli review                       # this branch's changes vs the default branch
npx mofu-cli review --base develop
npx mofu-cli review --pr 12 --comment     # review a GitHub PR and post it there

One model call on the diff. Findings come back as bugs, security issues, performance, simpler code or nits, each with a file and line and often a suggested fix. Mofu checks every finding against the diff, so a comment can only land on a line that changed. --comment posts a review on the pull request through the GitHub CLI (gh) after asking you first; --yes skips the question.

Fix a failing build

npx mofu-cli fix --run "npm test"     # reproduce, diagnose, fix on a branch
npx mofu-cli fix --log build.log
npx mofu-cli fix "TypeError: cannot read properties of undefined (reading 'address')"

Mofu runs the command (asking first), reads the failure and the files it points at, and tells you the root cause and the fix it proposes. Nothing changes until you say yes. Then it works on a mofu/… branch, makes the fix, runs the command again (up to three attempts) and commits. It won't weaken a test to make it pass.

Documentation

npx mofu-cli docs                       # write or update the README
npx mofu-cli docs "the API reference"

Mofu reads the code, proposes an outline and waits. Then it writes the files, and you see each diff before it's saved. Every command, flag and setting it documents has to exist in the code; what it can't find, it asks about instead of guessing.

Launch kit

npx mofu-cli launch-kit --name "Kitty Coin" --symbol KITTY --supply 1000000000

A fixed-supply ERC-20 for Robinhood Chain as a Foundry project: the contract, tests that run with forge test (no libraries to install), and deploy steps that keep your key in Foundry's encrypted keystore. The token has no owner, no mint, no blacklist, no fees and no upgrades, so there's nothing for Mofu's Token Scanner to flag in the code and no ownership to renounce. The kit runs mofu audit on it before you start. It covers the contract only, not liquidity or trading.

Commit messages and pull requests

npx mofu-cli commit            # message for what's staged (--all stages everything)
npx mofu-cli pr                # title and description, then push and open it with gh
npx mofu-cli pr --draft --base develop

One model call each. The commit message follows the style of your recent commits. You see the text first; git and gh run only after you say yes.

In the browser

Dev Tools in the app has Audit contract (paste Solidity or open a .sol file) and Find secrets (paste text, or a public GitHub repository). Both run in your browser: the code isn't sent to Mofu. The repository check reads the files as they are now; for every commit, run npx mofu-cli secrets.

GitHub Action

Run the secret scan, the contract check and the dependency check on every pull request, with one comment on the PR that updates itself. Add .github/workflows/mofu.yml: 

name: Mofu
on: pull_request
permissions:
  contents: read
  pull-requests: write
jobs:
  mofu:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: dev-mofu/mofu@main
        with:
          fail-on: secrets,risky   # also: deps, or none
          audit-path: contracts

On a pull request the secret scan reads only the commits the PR adds. The job fails on what you list in fail-on: secrets, risky (a contract the scanner would call risky, or a high-severity bug), deps (critical or high vulnerabilities). The same report runs locally with npx mofu-cli ci.

Your key and models

In the web app, open Settings and paste an OpenRouter key. It's checked, then kept in your browser and sent with each message only to call the model. With your own key there's no daily limit, and you can pick any OpenRouter model that supports tool calling.

The default model is Claude Haiku: fast, cheap and reliable with tools. In the CLI the model comes from --model, then the MOFU_MODEL variable, then "model" in ~/.mofu/config.json, then the default. Each CLI reply ends with a token count.

Local models

npx mofu-cli --local                         # Ollama at localhost:11434
npx mofu-cli --local -m qwen2.5-coder task "add a --verbose flag"
npx mofu-cli --base-url http://localhost:1234/v1   # LM Studio, llama.cpp, vLLM…

With --local or --base-url the CLI talks to an OpenAI-compatible server on your machine instead of OpenRouter: no API key, and your code never leaves your computer. Without -m it uses the first model the server lists. Your saved OpenRouter key is never sent to that server. MOFU_BASE_URL and MOFU_LOCAL_MODEL set the same things. Pick a model that supports tool calling (for example Qwen 2.5 Coder or Llama 3.1); small local models are slower and make more mistakes than hosted ones.

Privacy and data

  • Files are read in your browser. Only what's needed to answer (a data profile, the pages being read, package names, an endpoint list) is sent to the model.
  • Python runs on your device in a sandbox with no network access.
  • Messages pass through Mofu's server to the model provider via OpenRouter, whose own policies apply. Mofu's server doesn't store chats, files or keys.
  • The server keeps a daily message count per IP address, deleted after the day resets.
  • If you create a webhook, Mofu stores its URL, the tokens it watches, its secret and delivery counts until you delete it (or a week after it's switched off). Not your IP address.
  • Your browser keeps your settings, your key (if you add one), memory and flashcard progress. Use Remove key in Settings, Clear all in Memory, or clear your browser's site data.
  • In the terminal, everything runs on your machine. Your key and memory live in ~/.mofu/.

Troubleshooting

"You've used all 10 free messages for today"
Wait for the reset (midnight UTC) or add your own key in Settings.
"This PDF looks scanned"
The PDF is images of pages with no text layer. Try a PDF with selectable text.
GitHub rate limit
GitHub allows 60 anonymous requests an hour per IP. The app shows when the limit resets.
A spec or page link is refused
Mofu only fetches public addresses. For a spec on a local server, save it first (curl -o openapi.json http://localhost:3000/openapi.json) and load the file.
"No OpenRouter API key" in the CLI
Run npx mofu-cli auth or set OPENROUTER_API_KEY.
